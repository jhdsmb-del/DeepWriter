# 本地数据与安全运维

本文说明下载更新、任务暂停、完整备份和故障处理，补充[快速开始](QUICKSTART.md)与[隐私说明](PRIVACY.md)。

## 下载和更新前

从项目所有者提供的发行渠道取得安装包，并核对版本、平台与对应的 SHA-256 清单。Windows 可用 `Get-FileHash -LiteralPath '安装包的完整路径' -Algorithm SHA256` 计算哈希；文件名相同不代表内容相同。校验值只能说明文件与清单一致，不能独立证明发布者身份。

可直接下载公开发行包。将版本号换成 [Releases](https://github.com/jhdsmb-del/DeepWriter/releases) 上提供完整包的版本：

```powershell
$version = Read-Host "版本号（例如 8.0.0）"
gh release download "v$version" --repo jhdsmb-del/DeepWriter --pattern "DeepWriter-$version-complete.zip*" --dir ".\downloads\$version"
```

使用与下载版本对应的 SHA-256 清单，不混用旧版本文件。

完整 ZIP 解压后的 `complete-manifest.json` 记录版本、源码提交与文件哈希，`SHA256SUMS.txt` 是包内校验清单；桌面的 `desktop/installation-verification.json` 只绑定对应制品。保留整个 `cli` 目录及其 `runtime`，先运行 `.\cli\deepwriter.cmd --version`、`.\cli\deepwriter.cmd --help`，不要将启动器单独复制到别处。不要从压缩包预览窗口运行程序。

遇到系统安全提示时，先核对下载来源和哈希，不要关闭防护或以管理员权限运行来消除提示。

升级前先停止运行中的任务，处理未保存草稿，然后正常退出应用并备份。即使版本号相同，也应核对本次下载的哈希和发行说明。

## 暂停任务、查看用量与继续

桌面在任务中心查看运行状态、暂停原因、剩余预算和恢复入口。长文确认大纲后默认连续写作与审校；权限、预算或人工判断会使任务暂停，候选正文不等于已经完成的稿件。

CLI 在运行中按 Ctrl+C 保存并暂停；也可从另一终端发送控制命令。以下在完整包解压目录运行，`RUN` 换成实际运行 ID；指定过 `--data-dir` 时，查询和控制使用同一目录：

```powershell
.\cli\deepwriter.cmd list
.\cli\deepwriter.cmd status RUN --json
.\cli\deepwriter.cmd usage RUN --json
.\cli\deepwriter.cmd pause RUN
.\cli\deepwriter.cmd resume RUN
```

暂停可恢复，取消是终态；控制意图由执行进程在执行检查点处理，不直接杀 PID。等待实际状态变为暂停并完成保存，再退出或备份。恢复使用原模型、端点、凭据、目录与剩余预算，不扩大预算或换模型。未知副作用先检查 `recover-info RUN`，待人工审阅检查 `review RUN`；不要用“重新发一遍任务”代替决定。详细恢复命令见 [CLI 指南](CLI.md#暂停恢复与预算)。

完成后打开交付的稿件文件；重定向 CLI 的标准输出只能保存候选流。可恢复缺失的原稿件文件，已被你修改的同名文件不会被覆盖。用量或价格缺失显示为未知；实际费用请核对服务商账单。

上下文预览是本地估算与来源说明，不是服务商输入用量或账单。桌面有完整、优化、极简范围；运行接受后上下文相关配置被冻结，改设置只影响新任务。恢复遇到凭据/端点不匹配时，保持拒绝行为，不把 Key 或冻结配置改到其他服务尝试。

## 完整备份

1. 在任务中心检查运行状态，停止或处理仍在运行、等待授权、恢复受阻的任务。
2. 等待草稿保存完成。出现保存失败时选择重试；退出提示可返回应用处理。强制结束进程不能视为已完成保存。
3. 正常退出应用，确认进程已经结束，再复制完整 userData 目录。Windows 常见位置是 `%APPDATA%\DeepWriter`；实际路径可能随系统或启动配置不同，不要仅凭目录名猜测。
4. 另外备份所选工作目录、导出文件和外部创作项目。它们不一定在 userData 中。
5. 保存备份日期、应用版本和安装包哈希。备份应放在有访问控制的独立位置；需要离机保存时使用适当的加密存储。

备份整个目录，不要只复制 `deepwriter.db` 或手动删除数据库的 WAL/SHM 文件。运行中的 SQLite 数据库可能依赖伴随文件；应用退出失败时保留原目录，先处理故障，不应将热复制当作已验证的恢复备份。

会话、正文和未发送草稿可能是明文。凭据加密不代表整个用户目录已加密，备份同样属于敏感数据。

CLI 默认另存到启动时当前目录的 `.deepwriter-cli`，含数据库、非密钥配置、检查点、扩展版本和默认 `documents`。若使用了 `--data-dir`、`--doc-dir` 或自定义工作目录，按实际路径分别备份；它不在桌面 userData 中，也不会自动导入桌面历史。先等待 CLI 暂停和进程退出，再复制完整数据目录及外部稿件。Key 通常来自环境变量，不应为了备份而写入明文配置；完整包目录也不应混入用户数据。

## 恢复与迁移

恢复前正常退出应用，将当前 userData 完整另存，保留原始备份不动。先使用与备份匹配的应用版本；需要更新时，再按该版本支持的升级路径进行。恢复会替换一组相互关联的数据，不应把两份数据库、设置或事件文件混合拼接。

在用户确认目标目录后，把备份复制到正确的 userData 位置，再启动并核对会话、草稿、设置与任务状态。不要直接覆盖正在使用的目录，也不要通过删除当前数据来试错。

加密 Provider 凭据不能保证在另一系统账户或另一设备上解密。迁移后若凭据不可用，应在设置中重新配置 Provider；不要导出明文 Key 或关闭凭据保护。待发送附件与文件授权不能依赖备份自动恢复，需重新选择并确认授权。

恢复出来的任务不等于可以安全重放。对命令、写入、网络调用等未知副作用，先核对外部状态，再依照任务中心的原因决定。不要用重新发送消息替代恢复判断。

现有安装验收覆盖的具体升级起点、版本、提交和哈希见[验证记录](VALIDATION.md)。它不能证明所有旧版本升级、跨账户迁移或降级安全。不要用旧应用直接打开已由新版迁移的数据；需要退回旧版时使用升级前备份，并先确认该路径得到支持。

## 卸载与完整清理

安装配置默认保留 userData；卸载并不等于已删除历史、草稿、凭据、快照、导出或系统备份。重装也不等于全新配置。卸载前仍应按上述顺序备份，不把保留配置当作唯一备份。

若用户明确要求完整清理，应先核对准确的 userData 路径、工作目录、导出和所有备份副本。只处理明确选择的目标；删除聊天记录不能保证清除其它副本。系统凭据、系统备份及服务商保留的数据还可能有各自的清除流程。不要运行针对用户主目录、磁盘根目录或宽泛通配符的清理命令。

## 故障救援与反馈

| 情况 | 安全处理 |
| --- | --- |
| 草稿保存或退出失败 | 保留当前文字；重试保存或返回应用。不要把强制结束当作保存成功。 |
| 凭据存储不可用 | 检查系统凭据设施，在设置中重新配置；保持拒绝持久化行为。 |
| 升级后无法启动或迁移失败 | 保留当前目录和升级前备份，记录版本与步骤；不要手动修改数据库版本或删表。 |
| 任务恢复受阻或用量未知 | 阅读原因并核对外部副作用；不要直接重放或宣称零费用。 |
| 插件已停用、卸载或版本改变 | 原内容保留不等于执行许可保留；检查当前版本和启用状态，不替换旧任务的扩展 hash。 |
| CLI 找不到原会话或稿件 | 核对启动目录和 `--data-dir` / `--doc-dir`；不要把新建空目录当成原数据丢失。 |
| 稿件路径冲突或内容已改 | 保留用户文件与候选内容，按错误说明检查路径和 hash；不要覆盖来消除冲突。 |
| 安全扫描失败 | 不分发该制品；检查失败类别并重建、复验。扫描器诊断应脱敏，不粘贴原始秘密。 |

普通问题反馈提供应用版本、系统版本、触发步骤、预期和实际结果、必要的脱敏截图或日志。不要上传完整 userData、私人项目、真实 API Key、凭据文件或数据库；路径、文件名和正文也可能敏感。

怀疑 Key 暴露时，在 Provider 端撤销或轮换，并检查相应使用记录。删除本机记录不能撤回已经公开的秘密。安全漏洞通过[安全策略](../SECURITY.md)的私密渠道报告；若渠道未配置，应由项目所有者补齐，不应改为公开提交漏洞细节。

## 维护者：分发库存与通知资源

现有 SBOM 是依赖元数据记录，不等于完整的实际分发依赖审计。可对最终桌面 ASAR 和同一次构建的 Electron 目录采集库存：

```text
node scripts/distribution-inventory.cjs --asar dist/win-unpacked/resources/app.asar --electron-dir dist/win-unpacked --report release/distribution-inventory.json --notices release/THIRD_PARTY_NOTICES.txt
```

不提供 `--asar` 时只收集锁文件计划，退出码为 1，不能视为实际制品通过。退出码 0 表示已定义的 manifest/通知资源证据没有缺口，1 表示待复核项，2 表示工具或输入错误；任何退出码都不构成法律合规或完整发行验收结论。报告与通知文件只允许新建在项目根目录内，不覆盖已有证据；重复运行应选择新的证据路径。

报告分开列出锁文件计划、已安装元数据与实际 ASAR 包目录，核对打包版本和 lock 版本，并记录原始 manifest、许可/通知文件及 ASAR 的 SHA-256。实际 Electron `LICENSE` 与 `LICENSES.chromium.html` 缺失、打包许可证未知、通知缺失或元数据漂移会形成待复核项；其它平台的可选依赖未安装不会冒充实际制品缺失。

生成的通知还包含明确标记的“已安装锁文件计划补充”：这是为可能进入 JS bundle 的代码保留通知的保守集合，不代表这些包都已分发。bundle 内依赖、原生库、字体、图标和资源来源仍需维护者复核；许可证表达式不会被工具自动解释成兼容结论。确认后应把对应项目许可证、第三方通知和库存证据随该版本一起交付，而不是只留在构建机器上。

该工具不读取 userData、不调用模型、不安装或卸载、不改变仓库可见性，也不发布。版本、最终制品哈希、安全扫描、安装升级与退出保留的验收仍由发行流程独立执行。

## 重试尚未上传附件的发行

如果标签已经推送，但 Windows 发布作业因运行环境失败，保留原标签。维护者修好工作流后，可推送 `publish-retry/vX.Y.Z` 分支触发同一套发布步骤。该分支只提供工作流；应用、测试、指南和制品均从已有的 `vX.Y.Z` 标签构建，上传前再核对标签与制品来源一致。已正式发布的版本不会被覆盖。只做候选验证仍用 `release/vX.Y.Z`，不会上传附件。

## 发布 Windows 自动更新

在同一份源码上手动运行 GitHub Actions 的 **Windows Release** 和 **Windows NSIS update rehearsal**。前者将安装包、`latest.yml`、差分索引和 CLI 压缩包上传到草稿；后者在独立 Windows 机器上安装两个测试版本，检查正常退出不安装、主动重启会升级并保留数据。两者通过后，将同一提交的发布草稿设为最新正式版。客户端读取 GitHub 的正式发布，不读取草稿。
