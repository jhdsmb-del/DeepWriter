# DeepWriter 6.0.0

## 做一个能玩的故事

Galgame 工作室把制作过程收在四个步骤里：**项目与素材、剧情与分支、生成剧本、检查与试玩**。点一个玩家选项，能看到它通往的节点，再返回尝试另一条路。新项目可以从人物设定、立绘和场景图开始；已有项目则可以直接导入，沿原来的路线阅读和试玩。

生成剧本时先准备候选稿，成功后再写入。作者已有的剧本和同名素材会保留。导入作品的新剧情会给出确切文件和入口，例如把 `call` 加在原剧本中你想让这段故事发生的位置；重新检查后就可以试玩。试玩开启真正的 Ren’Py 窗口，关掉游戏或回工作室点停止都可以。

## 玩《末班渡船》

在完整包导入 `examples/last-ferry`。最后一班船离岸前，一张旧渡票把两个人牵到了一起。你有两种选择。它们不会绕回同一段结尾。

想先看台本，在完整包解压目录运行：

```powershell
.\cli\deepwriter.cmd galgame routes .\examples\last-ferry
```

终端列出选项、目标节点和脚本行号，加 `--json` 即可交给其他工具。

## 长回复不重复排版

工具状态、推理或文件回执更新时，已经显示的 Markdown 正文保持不动；新的正文到达时才重新解析。滚动、复制代码、引用和文件右键菜单继续按原来的方式使用。

在本地 Electron 对照里，同一份 13,576 字符回复接收 24 次推理更新，正文从重复解析 24 次变为 0 次；首次显示仍会解析正文。变化发生在桌面渲染，不改变模型输出。

在 Windows 上，旧会话的文件回执和工作区的禁止访问规则都能识别同一文件的 8.3 短路径。
