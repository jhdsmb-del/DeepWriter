# DeepWriter 5.0.0

## 改主意时，接着说就行

比如 Agent 正在核对两批稿件，你发现乙组更急。直接发「先查乙组，甲组等我补资料」。这句话会进入当前任务，等当前工具结束，在下一次模型请求前按发送顺序生效。已经执行的写入不会重做。暂停时还没用到的补充可以在恢复后接着处理。

在另一个终端也可以做同一件事：

```powershell
deepwriter steer RUN "先查乙组，不要修改甲组"
deepwriter steering RUN
deepwriter status RUN
```

## 长对话里可以找原话

不用把半个月前的需求再贴一遍。问「最初定的那串编号是什么？找我的原话」，Agent 可以在本会话中查回早期消息，并区分是你说的还是它答的。恢复旧任务时，历史查询以该任务开始时的记录为准；你在任务进行中主动补充的内容，会作为新指令收到。

## 要不要设上限，由你决定

新配置不设整项任务的调用次数、轮数、累计 token、耗时或费用上限。桌面的入口在 **设置 → 完成与预算**；CLI 可以只给某次工作指定上限。正在运行的任务仍按启动时约定好的设置执行。

联网使用当前服务商提供的联网服务和你配置的凭据，不切到免费搜索代理。想离线可以手动关闭。思考默认交给服务商和模型；需要指定时再选择该模型支持的方式。

## 单次输出结束，不等于整件事结束

模型因为单次输出长度而截断时，普通 Agent 会接着写，较早的部分保留在最终回复中。截断的是工具参数时，不会拿半条参数去改文件。多步任务还有后续工作，并且确实取得了新进展，就能继续，不再受整次任务“一次提醒”的限制。
