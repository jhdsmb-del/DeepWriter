# DeepWriter v1.2.4 Beta

> Windows x64 · Beta candidate · 不是稳定版

v1.2.4 收敛了几条写作工作流的边界：事实性事件需要真实的“已经发生”证据；纯文稿可以在不虚构结构化事实的前提下被用户接受；复核中断后可以从持久化状态继续；故事账本使用严格的父节点 hash chain。它仍是 Beta，不宣告 RC、released 或 1.0。

## 本轮变化

### 事实性事件门禁

- 事件抽取区分已断言发生、拒绝、计划、尝试、传闻、回忆、引用等语义。
- 只有满足局部角色和谓词证据的“已发生”事件，才可以写入人物、物件或关系状态；普通出现“把”“给”等字样不会单独改变故事事实。
- 这是一组生产路径的边界与回归检查，不等同于完整的中文理解或写作质量证明；真实模型仍需按自己的 Provider 单独评估。

### 无状态文稿接受

- 当一段文字只需要作为正文，而没有可靠的结构化事实变化时，用户可以明确选择“接受正文，不写入状态”。
- 该选择会留下可追溯的复核证据，并保留正文；它不会猜测人物持有者、事件结果或其他状态。
- 同时包含未解决结构化歧义的混合内容不会借此放行；`accept_unknown` 仍只适用于允许的角色绑定歧义。

### 复核与崩溃恢复

- 复核决定、版本、审查快照和最终包都落在持久化路径中，进程在提交后、最终响应前中断时仍可恢复。
- 重启后使用相同的决定标识可以继续完成同一事务；重复重试返回同一权威终态，冲突载荷会拒绝。
- 恢复检查使用合成 Provider，不代表真实网络故障、所有 Electron 环境或任意外部工具都已完成长期验证。

### 严格故事账本与后代撤回

- 故事账本节点现在包含 `parentHash`、`nodeType` 和 `hashSchemaVersion`；读取时检查 revision 连续性、父 hash、节点 hash、唯一节点类型与 head hash，缺节点、篡改、断档、双节点或 head 不符都会 fail-closed。
- v1 旧节点不会与 v2 静默混用。v23/v24 数据库通过新增 v25 迁移在事务内校验并重算为 v2，并以 durable meta 记录迁移策略；迁移异常时不继续打开损坏链。
- 撤回以 append-only retraction 节点记录。被撤回 revision 的后代一律标记为 stale 并从权威上下文排除；当前版本没有现成的 revalidate/rebase 入口，恢复需要未来的显式能力或重新建立安全分支。旧节点和撤回证据仍保留供审计。

## 可复核入口

```powershell
npm ci
npm run typecheck
npm run r65:actuality-contract
npm run r65:review-recovery
npm run p2:story-ledger-integrity
```

这些门禁默认不发送真实 Provider 请求；其中的模型输出与网络故障场景是 synthetic，不能据此推导费用、速度或文风质量。

## 仍未完成

- 真实 Provider 写作基准和长时间 soak（包括真实 API 费用、质量与稳定性）未完成。
- 商业代码签名、干净多机 Windows 安装/升级/卸载矩阵、SmartScreen/UAC 和 NVDA 人工验证未完成。
- ARM64、macOS/Linux 及其他桌面平台未提供安装包。
- 本版本目标仍为 Windows x64；请备份重要稿件，并把 Beta 当作测试版本使用。
