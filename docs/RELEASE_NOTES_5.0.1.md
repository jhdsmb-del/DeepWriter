# DeepWriter 5.0.1

## 从回复打开写好的文件

让 Agent「读素材.md，把要点保存为总结.md」。完成后，右键回复中的 `总结.md`，选择**打开文件**或**在文件资源管理器中显示**。同名文件按该任务的实际位置区分。文件移走了，DeepWriter 会告诉你，不会改去打开另一份。

Agent 说“写好了”不再算交付：普通文件任务会核对写入结果。只有文字答复、写错路径或没有获得权限时，不会把不存在的文件报成已完成。

## 把授权留给真正需要决定的操作

选好工作区后，自动模式放行日常的文档读取、新建与可撤销的局部编辑。覆盖已有文件或需要额外授权时，弹窗显示具体操作、路径或命令。以前选的严格模式继续有效。

## 长回复更流畅

普通 Agent 长聊时，尽量让相邻请求复用同一段历史；新更正和原话仍优先。长正文、推理文字和长工具参数边到达边增量处理，不再为新来的一小段反复扫描前面的全部文字。界面中的实际缓存命中取自服务商返回的数据。

用同一段含 65,536 个正文字符和等长推理的本地数据流对比，端到端处理从 4.20 秒降至 2.71 秒。另一组 90 条消息的长对话中，相邻请求可复用的 JSON 前缀约从 1.9 KB 增至 8.8–9.4 KB；这衡量的是可复用输入，服务商实际命中另计。[DeepSeek 缓存计量](https://api-docs.deepseek.com/guides/kv_cache/)

## 发出任务和点开文件更快

长会话准备第一条模型请求时，不再反复估算同一段历史。400 条历史的本地对照中，新建运行环境从发起任务到请求发出由 166 毫秒降至 53 毫秒；复用同一环境时由 156 毫秒降至 44 毫秒。请求内容没有缩减。

打开含很多文件的旧回复时，文件回执按任务一次读取。64 个文件的对照由 192 次数据库查询减为 3 次，解析耗时从 338 毫秒降至 54 毫秒。弹出菜单不先读完整篇稿件；真正选择打开时，仍核对目标是不是那份文件。

模型菜单和设置面板共用同一份模型目录。关掉再打开不必重新等一遍；修改供应商或模型时仍会刷新。任务详情切换到另一项任务时，会撤下上一项的账单再显示新数据。
