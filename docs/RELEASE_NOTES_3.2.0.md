# DeepWriter 3.2.0

## 工作 Agent：引用真正找到的那一段

例如：「在《交接记录》里找到原话“柜[A]+”，说说紧跟着的柜号和交接人，附上行号。」方括号和加号可以按原样查找。即使命中远在一行的几千字之后，Agent 也能从那个位置继续读，而不是只看到段首。文件没读完或部分资料打不开时，工具会说明实际查了多少。

桌面和终端都能直接读工作目录里的 Word 稿件。给出 .docx 文件名，Agent 可以逐段取原文、引用其中的约定，不改动 Word 文件。

## 写作：说明文不再被当成小说

在「长文」里写「给新同事写一份灯塔交接指南」，采访围绕读者、事实和步骤展开。换成「写一篇灯塔守夜人的小说」，才按人物与场景梳理。要求没说清用什么写法时，可以在原有采访里选择，也可以自由填写。

确认大纲后，说明与论述按各节目的和材料写；小说保留场景接续和视角约束。作者选过「不适用」的维度不会被要求作为事实来源。已有采访和已开始的正文保留当时确认的约定。

刚回答第一题也可以关掉应用。回来后从会话列表点那篇稿子，接着上次的问题写；开始正文时，使用的是你实际批准的那份大纲。

手里有素材，直接在长文页添加。每篇稿子记住自己选过的文件，切去写另一篇不会换掉原稿的材料。重新打开后如果文件授权过期，会点名请你重选原文件。

如果说明文首节写得太长，DeepWriter 会尽量在句末收住，继续写后面的节，而不是因为总字数够了就提前导出。开启审校时，沿用同一次审校看本节是否讲到了大纲约定的内容；不开审校，也会依次写各节。

## Galgame：用自己的 Ren’Py

项目名旁显示正在使用的 SDK 版本。可以手动选择本机的 7 系或 8 系 SDK；已有项目不必为了检查剧本而换到下载按钮提供的 8.5.3。切换版本会保留脚本和素材，并要求用新版本重新检查。Windows 实测 7.8.7、8.5.2、8.5.3：三者均能创建项目，报告有语法错误的剧本，并在修复后通过检查。

同一角色可以同时拥有「微笑」和「惊讶」两张立绘。DeepWriter 按实际生成的图片标签交给制作 Agent，不再把中文表情名都当成同一个默认表情。
