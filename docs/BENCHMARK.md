> 状态：**框架就绪（2026-08-11）**。`scripts/benchmark.ts` 已建立：指标结构（TTFT p50/p95、稳定 tok/s、有效汉字/s、总耗时、cache-hit/miss、output、reasoning、工具轮数、重试、采用率、人工修改率、事实/连续性错误）、任务集（novel-scene / style-candidate / agent-tool-loop）、策略对比（baseline / memorypack / agent-full）、发布声明门槛判定（总耗时 ↓≥20% 或 cache-miss+output ↓≥25% 且质量非劣 ≤2pp）。mock 模式已验证管道（`node out/benchmark.mjs --mock`），真实 API 模式待接线（需 DEEPSEEK_API_KEY，消耗额度）。**mock 结果不代表真实性能**；任何「高保真」「已优于基线」的宣称必须先过本文档门槛，否则按 docs/PROJECT_REVIEW.md 第十四节口径禁止声称。
> 口径来源：docs/style-fidelity.md §13.3 正文生成器 / §13.4 风格差异评审器 / §13.5 局部修订器；docs/REMEDIATION_REPORT.md 未解决事项与禁止声称项。

## 一、目的

为风格高保真 Pipeline（stylev2）与长文生成建立可复现的量化验收协议，防止「自评即达标」的循环论证：

1. **固定测试集**——用例、语料、种子全部冻结，跑分可复现；
2. **基线对比**——任何正向结论必须相对显式基线得出；
3. **指标门槛**——给出通过线，未过线不得宣称达标。

## 二、固定测试集要求（Fixed Test Set）

测试集与语料必须满足以下条件，缺失任一条件视为「测试集未冻结」：

| 要求 | 说明 |
|---|---|
| 场景类型覆盖 | 每档测试 ≥6 种场景类型：对白场景、心理描写、动作场景、环境描写、倒叙/插叙、群像对话（对应 13.4 六维评分全部可评） |
| 事实约束包 | 每个用例附显式 facts 清单（人物/时间线/地点/专名/事件顺序），生成正文不得改变（13.3「故事事实」优先级高于风格规则） |
| 骨架固定 | 每个用例固定 SCENE_SKELETON（13.3），基线组与实验组使用同一骨架，仅风格注入不同 |
| 防泄漏 holdout | 测试文本与示例池（exemplars）严格分离；语料切分为 profile/example/holdout 三分（复用 [21] 组协议），测试文本不得出现在语料与示例中 |
| 用例数量 | 每档 ≥10 用例 × 每用例 ≥3 候选（可做统计显著性与方差估计） |
| 冻结存档 | 用例 JSON + 语料哈希 + 模型/温度/最大 tokens 配置一并存档于 docs/benchmarks/testset-v1.json（含 sha256） |

## 三、基线对比协议（Baseline Protocol）

| 对比组 | 定义 |
|---|---|
| 基线 A（无风格约束） | 默认 system prompt 直接生成，无画像/规则/示例注入 |
| 基线 B（画像注入） | 高保真管道：规则编译 + 骨架抽取 + 示例映射 + 三变体候选（13.3） |
| 对照方式 | 同用例同骨架同种子，A/B 两两对比，仅作者风格证据注入与否不同 |
| 评审器 | 固定使用 13.4 风格差异评审提示词（六维 + span/ruleID 证据），禁止评审器接触语料原文（只给「未参与生成的作者风格证据」） |
| 双盲 | 评分方看不到候选来源标签（A/B 随机打乱）；候选文本去除特征性人名/专名后评分 |

## 四、指标与通过线（Metrics & Pass Line）

| 指标 | 定义 | 通过线（Proposed，待定稿） |
|---|---|---|
| 风格差异分 | 13.4 六维（句法节奏/段落组织/对白处理/叙事距离/信息释放/修辞与自然度）各 0–1 的均值 | 基线 B 相对基线 A 提升 ≥ +0.15 |
| 事实保真 | facts 清单命中率（生成文本覆盖/未篡改事实的比例，13.5 preserveFacts） | ≥ 0.90，且新增事实数为 0 |
| 防复制 | 生成文本与语料最长公共连续片段（复用 [20] 防复制检测） | 最长公共片段 < 12 字，全库零匹配 |
| 规则合规 | 生成文本中 StyleRuleSet 条件规则被触发且未违反的比例 | ≥ 0.85 |
| 优先级校验 | 安全/用户禁令 > 事实 > 人物一致性 > 场景功能 > 风格规则 > 字数（13.3 优先级） | 任意用例出现「风格表达与事实冲突时以风格优先」即失败 |
| 字数达标 | 输出长度相对目标区间偏差 | ≤ ±15% |

全部指标同时过线 = 该档「达标」；任一失败即整档不达标，禁止局部宣称。

### 独立模型基准的可选费用上限

`npm run benchmark` 仍运行本地 synthetic/mock 管道。独立的 `scripts/benchmark-real.ts` 保留原 `--real` 调用方式；费用上限需要调用者显式设置，不继承桌面 Agent 的默认配置。

运行 `node out/benchmark-real.mjs --help` 查看参数。若为真实基准设置 `--max-cost-cny=N`，还需提供 `--price-profile=PATH`、`--trust-price-profile-hash=SHA` 与 `--pricing-provider-id=ID`。价格必须精确匹配本次模型、请求 origin 和 CNY；缺失、未知或漂移的价格在 fetch 前拒绝。mock 费用测试使用新建本地服务的 synthetic 价格，不需要真实报价或凭据。

该金额是整次运行的共同上限，包含所有样本、失败和重试的完整预请求费用上界，不会按样本重置。JSONL 头部的 `budget` 记录上限、已计上界和获准请求数；上界不是实际账单。费用拒绝退出码为 2。
