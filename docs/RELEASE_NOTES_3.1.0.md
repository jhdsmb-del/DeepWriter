# DeepWriter 3.1.0

从一份已有的稿子开始。在稿件目录写下项目约定，让 Agent 先审一遍，再决定要不要改。

**留下写作约定。** 桌面在「设置 → 项目约定」编辑；终端用 `brief show` 查看，或用 `brief init --input 写作要求.txt` 导入。新对话使用当前目录里的 `DEEPWRITER.md`。长文采访、大纲和正文沿用采访开始时的版本，修改约定不会悄悄改写旧任务。

**先审，不急着写。** 打开 Agent 的「更多工具 → 只读审阅」。它可以定位原文并提出方案，但不能修改稿件、执行命令或启动插件。看完点「批准执行」，或拒绝这一版。终端对应 `plan`、`plan-info`、`approve`、`reject-plan`；批准不会跳过原有的写入授权。

**隔天仍能看见改了什么。** 重新打开桌面会话，展开当时的回复查看文件名、原稿行号和修改前后的文字。即便作者后来又改过文件，回执仍是当时的内容。终端用 `/changes` 看当前会话，用 `changes RUN` 看某次执行。

**长文接着上一场写。** 新场景获得前一场已经收进稿件的结尾。当前场景续写时可以接上本场最近的段落，不需要反复把整部书带进请求。如果所有场景都已收稿但还没达到目标字数，Agent 会接着最后一场补写收尾，再导出完整稿件。

**服务商没返回缓存明细，也能继续查稿。** 如果此次请求已经按可计算的费用上限记账，下一步会按剩余预算继续，不会把缺项当成余额用尽。下一步可能超过限额时，仍会在发送前停止。
